# 集成检查清单

将现成实现集成到当前项目之前，逐项确认。

## 许可证

- [ ] 确认许可证类型，且与本项目许可证兼容
- [ ] 按许可证要求保留版权声明与 LICENSE 文本
- [ ] GPL/AGPL 项目已评估传染性影响

## 代码质量

- [ ] 已通读核心逻辑，理解其行为与边界条件
- [ ] 已知问题（issue 中的 open bug）不影响本项目场景
- [ ] 性能满足当前规模需求（注意大数据量、并发场景）

## 依赖与兼容性

- [ ] 依赖链完整且均在维护中
- [ ] 语言/框架版本与当前项目匹配
- [ ] 在目标平台（操作系统、运行时）验证可用

## 安全

- [ ] 无已知 CVE（可在 GitHub Advisory / Snyk 查询）
- [ ] 涉及网络、文件、执行外部命令的部分已审查
- [ ] 不包含可疑代码（混淆、远程加载、硬编码凭据）

## 集成方式

- [ ] 优先作为依赖引入；确需改源码时 fork 并记录来源与改动点
- [ ] 修复现有问题而非推倒重写；确需重写时说明理由
- [ ] 改造部分与原实现做了清晰隔离/注释，便于后续跟进上游更新

## 验证

- [ ] 集成后运行原有测试，确认无回归
- [ ] 为集成点补充测试（边界条件、失败路径）
- [ ] 在项目文档中记录复用来源、版本与许可证
